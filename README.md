# Word 加密文档自动打开器

右键加密的 Word 文档 -> 发送到 -> **打开需求文档**，自动输入密码打开，无需每次手动输密码。

适用场景：团队共享的 Word 文档使用统一密码加密（如共享目录、邮件、版本库分发），每次打开都要输入同一密码。

## 适用前提

- Windows + **Microsoft Office（Word）**。WPS 暂不支持。
- 文档使用"打开密码"加密，且你知道该密码。

## 安装（一次性，约 1 分钟）

1. 解压本工具包到任意目录。
2. 双击 **install.bat**。
3. 按提示输入 Word 文档密码（屏幕显示为星号）并回车。
4. 看到"安装完成"即成功。

> 密码以 Windows DPAPI 加密保存在本机 `C:\Users\<你的用户名>\.docpw`，仅当前 Windows 账户可解密，不会明文落盘，也不会发送到任何地方。

## 日常使用

1. 在文件夹/共享目录中找到加密的 Word 文档。
2. 右键 -> 发送到 -> **打开需求文档**。
3. 文档直接打开，不再询问密码。

## 原理（简述）

安装时把核心脚本复制到 `%USERPROFILE%\tools\open-doc.ps1`，并在"发送到"菜单注册入口。使用时脚本解密本地密码，通过 Word COM 接口（`Documents.Open` 的密码参数）打开文档——文档始终保持加密状态，**不产生明文副本**，更新后的新版本同样适用。

## 安全注意事项

1. `.docpw` 是敏感文件：**禁止**放入版本库检出目录、网盘同步目录、共享盘。
2. 本工具只自动化"输入你已知且有权限的密码"，不绕过任何访问控制，不生成明文副本。
3. 若所在组织有制度明确禁止自动化处理受控文档，请先与主管/IT 确认后再使用。
4. 请勿把密码明文发给任何人。

## 常见问题

**打开时黑框一闪而过、文档没打开**
- 确认已执行过 install.bat 并成功设置密码。
- 确认电脑安装的是 Microsoft Office（非 WPS）。
- 手动诊断：在 PowerShell 运行
  `powershell -NoProfile -ExecutionPolicy Bypass -File C:\Users\<你的用户名>\tools\open-doc.ps1 "文档完整路径"`
  查看屏幕输出的错误信息。

**密码变了**
删除 `C:\Users\<你的用户名>\.docpw`，重新双击 install.bat 并输入新密码。

**换电脑/换 Windows 账户**
需要重新执行一次安装（密码文件绑定账户，不能拷贝使用）。

**误发给没有加密的 Word 文档**
不影响——密码参数会被忽略，文档正常打开。

## 卸载

双击 **uninstall.bat**，移除右键菜单项与核心脚本。密码文件默认保留，如需彻底清除请手动删除 `.docpw`。

---
*维护备注：PowerShell 5.1 对无 BOM 的 UTF-8 脚本按系统 ANSI 解码会导致中文乱码报错，所有 .ps1 必须保存为 UTF-8 with BOM；修改过 .ps1 后需重新加 BOM。*
